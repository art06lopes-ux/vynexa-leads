## Arquitetura

```
src/
  app/(painel)/        telas (Server Components; interação em components/)
  app/api/             rotas — todas passam por server/api.ts (sessão + erro legível)
  components/          interface (shell, leads, busca, perfil, crm, campanhas, …)
  db/                  consultas de leitura (leads, painel, campanhas, vendas)
  services/            regras de negócio puras ou com banco (score, dedup,
                       registro, campanhas, envio, financeiro, supressão, CRM…)
  integrations/        adaptadores trocáveis
    leads/             LeadProvider: GooglePlacesProvider, OsmProvider, CSV
    ai/                AIProvider (Gemini) + agentes: LeadAnalyzer,
                       SalesOpportunityAnalyzer, MessageGenerator, EmailGenerator,
                       FollowUpGenerator, ProposalGenerator, QueryParser
    email/             EmailProvider: Gmail, Resend, SMTP (Hostinger)
    pagamentos/        PaymentProvider: Asaas
    notificacoes/      NotificationProvider: central (banco) + push
    segredos.ts        chaves de API cifradas (AES-GCM) no banco
  worker/              fila (GitHub Actions) + handlers; fila.ts também roda
                       jobs na hora via after() nas rotas
db/migracoes/          SQL (0012 = v2)
```

Toda fonte de empresas entrega `LugarEncontrado` e passa por
`services/registro.ts`: dedup → supressão → score → lead → histórico.

### Regras que o código garante

- **Nada inventado.** Campo que a fonte não trouxe fica nulo. A saída da
  IA é rejeitada se citar número que não está nos dados (ex.: "300
  avaliações" quando são 47), se tiver placeholder ou se cumprimentar o
  remetente.
- **Nada sai sem autorização.** WhatsApp só abre a conversa. Campanha só
  envia depois de `autorizada_em` (o operador vê os previews). Follow-up
  só existe se foi ligado na criação, e é cancelado se o lead respondeu.
- **Fila com ritmo.** E-mails por hora, limite por campanha e teto global
  diário (Configurações → E-mail).
- **Opt-out.** Todo e-mail tem link de descadastro (página com
  confirmação + one-click RFC 8058). Pediu para sair → NÃO CONTATAR,
  envios pendentes cancelados, contatos na lista de supressão; se a
  empresa aparecer de novo em outra busca, já nasce bloqueada.
- **Segredos só no servidor**, cifrados no banco; a tela vê os 4 últimos
  caracteres. Webhooks validados (token do Asaas, assinatura Svix do
  Resend, HMAC da Stripe). Links rastreados assinados (sem redirecionador
  aberto). Rate limit no login, buscas, IA e envio avulso.

## Configuração (tudo pela tela, em Configurações)

1. **Identidade**: nome, responsável, e-mail, WhatsApp, cores, assinatura e
   **logo** (aparece no painel, e-mails, propostas, notificações).
2. **Produtos**: "Criar catálogo inicial" e defina preços. A IA escolhe o
   produto daqui; a proposta usa os entregáveis cadastrados.
3. **Integrações**:
   - Google Places API (New) — exige conta de faturamento **com cartão** no
     Google Cloud. Telefone/site/avaliações são SKU Enterprise (cota mensal
     gratuita, cobrança acima). Cada busca tem teto de requisições.
   - Gemini — gratuito, sem cartão.
   - Resend ou senha SMTP (Hostinger), e/ou Gmail na aba E-mail.
   - Asaas — comece pelo sandbox; token do webhook inventado por você.
4. **E-mail**: provedor ativo, remetente, SMTP, teto diário, "Enviar e-mail
   de teste para mim".
5. **Pagamentos**: ambiente do Asaas e a URL do webhook para cadastrar lá.
6. **Avançado**: endereço público (`app_url`, usado nos links dos e-mails).

## Colocar no ar (passos que dependem de decisão)

1. **Backup**: o D1 tem Time Travel (restauração a um instante). Anote o
   horário antes de migrar.
2. Aplicar a migração na produção: `npm run db:aplicar` (com as credenciais
   do D1 no ambiente). A 0012 recria empresas/leads/campanhas/envios/vendas
   e guarda cópias em `bak12_*`.
3. `npm run v2:pos-migracao` — chaves de dedup e score v2 para as empresas
   existentes (~8 mil linhas, cabe na cota diária do D1).
4. Conferir as contagens contra `bak12_*`; só então criar uma 0013 que
   apaga as cópias.
5. Merge da branch e deploy na Vercel. O worker (GitHub Actions) não
   precisa de segredo novo: as chaves novas vêm do banco.

> Atenção: o `.env.local` aponta para o D1 de produção. O
> `.env.development.local` (não versionado) força o banco local no
> `next dev`. Scripts (`db:aplicar`, `worker`, `v2:pos-migracao`) usam o
> `.env.local` — rodam na produção se você não sobrescrever as variáveis.
